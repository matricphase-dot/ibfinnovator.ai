## STEP 1: Add Domain to Cloudflare & Change Nameservers

### 1.1 In Cloudflare Dashboard
1. Log in to [Cloudflare](https://dash.cloudflare.com/) (create a free account if you haven't yet).
2. Click **+ Add a Domain** (or **Add a site**).
3. Enter your domain: `innovators-global.com` (or `innovator-global.com`).
4. Select the **Free Plan** ($0/month).
5. Cloudflare will automatically scan and import existing DNS records.
6. Cloudflare will display **two assigned nameservers**, for example:
   - `alina.ns.cloudflare.com`
   - `brad.ns.cloudflare.com`

### 1.2 In Your Domain Registrar (e.g. GoDaddy)
1. Log into your registrar where you bought the domain (currently using GoDaddy nameservers `ns39.domaincontrol.com` / `ns40.domaincontrol.com`).
2. Go to **Domains** → Select `innovators-global.com` → **Manage DNS**.
3. Locate **Nameservers** → Click **Change Nameservers**.
4. Select **I'll use my own nameservers** (Custom).
5. Paste the two Cloudflare nameservers provided in step 1.1.
6. Save and confirm.
7. Return to Cloudflare and click **Check nameservers now**.  
   *(Propagation usually takes 5 to 15 minutes).*

## STEP 2: Launch & Configure AWS EC2 Instance (`c7i-flex.large`)

### 2.1 Launch Instance in AWS Management Console
1. Log into the [AWS Console](https://console.aws.amazon.com/ec2).
2. Ensure you are in your preferred region (e.g., `ap-south-1` Mumbai or `us-east-1`).
3. Click **Launch Instance**:
   - **Name:** `innovators-production-app`
   - **OS Image (AMI):** **Ubuntu Server 24.04 LTS (HVM), SSD Volume Type (64-bit x86)**
   - **Instance Type:** **`c7i-flex.large`** (2 vCPU, 4 GiB RAM, 4th Gen Xeon — covered by your AWS credits)
   - **Key Pair:** Create or select an existing `.pem` key pair (e.g., `innovators-key.pem`).
4. **Network / Security Group Settings**:
   - Check **Allow SSH traffic from:** `My IP` (or `0.0.0.0/0` if working across networks).
   - Check **Allow HTTP traffic from the internet** (Port 80).
   - Check **Allow HTTPS traffic from the internet** (Port 443).
5. **Storage (EBS)**:
   - Set Root volume to **30 GiB gp3** (or gp2).
6. Click **Launch Instance**.

### 2.2 Allocate & Associate an Elastic IP (Critical Step)
> Without an Elastic IP, your server IP will change every time you reboot the instance, which will break your Cloudflare DNS!
1. In the EC2 Left Sidebar, navigate to **Network & Security → Elastic IPs**.
2. Click **Allocate Elastic IP address** → Click **Allocate**.
3. Select the newly allocated IP → Click **Actions → Associate Elastic IP address**.
4. Choose:
   - **Resource type:** `Instance`
   - **Instance:** Select `innovators-production-app`.
5. Click **Associate**.
6. **Note down this Elastic IP** (e.g., `13.234.X.X`).

## STEP 3: Server Provisioning (Node.js 22, Redis, Nginx, PM2)

Connect to your EC2 instance via SSH:
```bash
ssh -i "innovators-key.pem" ubuntu@YOUR_ELASTIC_IP
```

Run the following setup commands on the server:

### 3.1 Update System & Install Core Packages
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git ufw redis-server nginx build-essential
```

### 3.2 Install Node.js 22 LTS
```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v # Should display v22.x
npm -v
```

### 3.3 Configure & Verify Local Redis
```bash
# Verify Redis is running locally on port 6379
sudo systemctl enable redis-server
sudo systemctl start redis-server
redis-cli ping
# Output must be: PONG
```

### 3.4 Install PM2 Globally
```bash
sudo npm install -g pm2
pm2 startup systemd
# Run the command generated by the output to enable startup hook
```

## STEP 4: Configure Cloudflare DNS & SSL

Now that you have your **Elastic IP** from Step 2.2:

### 4.1 Cloudflare DNS Records
In your **Cloudflare Dashboard → DNS → Records**, set up the following records:

| Type | Name | Content (IPv4) | Proxy Status | Purpose |
|---|---|---|---|---|
| **A** | `@` (or `innovators-global.com`) | `YOUR_ELASTIC_IP` | **Proxied** (Orange Cloud) | Root landing & `/@username` portfolios |
| **A** | `app` | `YOUR_ELASTIC_IP` | **Proxied** (Orange Cloud) | Authenticated Startup OS workspace |
| **CNAME** | `www` | `innovators-global.com` | **Proxied** (Orange Cloud) | Redirects www traffic |

### 4.2 Cloudflare SSL/TLS Configuration
1. Go to **SSL/TLS → Overview** → Set encryption mode to **Full (Strict)**.
2. Go to **SSL/TLS → Edge Certificates**:
   - Turn **Always Use HTTPS** to **ON**.
   - Set **Minimum TLS Version** to **TLS 1.2**.
   - Turn **Automatic HTTPS Rewrites** to **ON**.

### 4.3 Generate Cloudflare Origin Certificate for Nginx
To achieve true end-to-end encryption between Cloudflare and your EC2 instance:
1. Go to **SSL/TLS → Origin Server** → Click **Create Certificate**.
2. Keep default options (`*.innovators-global.com`, `innovators-global.com` valid for 15 years).
3. Click **Create**.
4. On your EC2 server, save these keys:
   ```bash
   sudo mkdir -p /etc/ssl/cloudflare
   sudo nano /etc/ssl/cloudflare/cert.pem  # Paste Origin Certificate
   sudo nano /etc/ssl/cloudflare/key.pem   # Paste Private Key
   sudo chmod 600 /etc/ssl/cloudflare/key.pem
   ```

## STEP 5: Configure Nginx Reverse Proxy on EC2

Create the Nginx configuration file:
```bash
sudo nano /etc/nginx/sites-available/innovators
```

Paste the following production Nginx configuration:

```nginx
# Upstream Next.js Node cluster
upstream nextjs_cluster {
    server 127.0.0.1:3000;
    keepalive 64;
}

# 1. HTTP -> HTTPS Redirect
server {
    listen 80;
    listen [::]:80;
    server_name innovators-global.com www.innovators-global.com app.innovators-global.com;
    return 301 https://$host$request_uri;
}

# 2. HTTPS Server (Cloudflare Origin SSL)
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name innovators-global.com www.innovators-global.com app.innovators-global.com;

    # Cloudflare Origin Certificates
    ssl_certificate /etc/ssl/cloudflare/cert.pem;
    ssl_certificate_key /etc/ssl/cloudflare/key.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # Gzip Compression
    gzip on;
    gzip_proxied any;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml+rss text/javascript image/svg+xml;

    # Static assets caching
    location /_next/static/ {
        alias /var/www/innovators/.next/static/;
        expires 365d;
        access_log off;
    }

    location /public/ {
        alias /var/www/innovators/public/;
        expires 30d;
        access_log off;
    }

    # Main reverse proxy to Next.js
    location / {
        proxy_pass http://nextjs_cluster;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        set $real_client_ip $http_cf_connecting_ip;
        if ($real_client_ip = "") {
            set $real_client_ip $remote_addr;
        }
        proxy_set_header X-Real-IP $real_client_ip;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        set $forwarded_proto $http_x_forwarded_proto;
        if ($forwarded_proto = "") {
            set $forwarded_proto $scheme;
        }
        proxy_set_header X-Forwarded-Proto $forwarded_proto;
        proxy_cache_bypass $http_upgrade;
        proxy_read_timeout 60s;
        proxy_connect_timeout 60s;
    }
}
```

Enable the site and reload Nginx:
```bash
sudo ln -sf /etc/nginx/sites-available/innovators /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

## STEP 6: Deploy App & Configure PM2 Cluster

On your EC2 server:

```bash
# 1. Clone repository to /var/www/innovators
sudo mkdir -p /var/www/innovators
sudo chown -R ubuntu:ubuntu /var/www/innovators
git clone https://github.com/matricphase-dot/ibfinnovator.ai.git /var/www/innovators
cd /var/www/innovators

# 2. Install dependencies & build
npm ci
cp .env.local.example .env.local  # Populate with your Supabase keys
npm run build

# 3. Create PM2 configuration (ecosystem.config.cjs)
cat << 'EOF' > ecosystem.config.cjs
module.exports = {
  apps: [{
    name: "innovators-app",
    script: "node_modules/next/dist/bin/next",
    args: "start -p 3000",
    instances: 2, // 2 vCPUs on c7i-flex.large
    exec_mode: "cluster",
    watch: false,
    env: {
      NODE_ENV: "production",
      PORT: 3000
    }
  }]
};
EOF

# 4. Start the application with PM2
pm2 start ecosystem.config.cjs
pm2 save
```

## STEP 7: Cloudflare Edge Caching Rules for `/@username` Portfolios

This ensures that public link-in-bio pages never hit your EC2 CPU and are served from Cloudflare's global edge cache (<10ms):

1. Go to **Cloudflare Dashboard → Caching → Cache Rules** → Click **Create rule**.
2. **Rule Name:** `Cache Public Portfolios`
3. **When incoming requests match:**
   - Field: `URI Path`
   - Operator: `starts with`
   - Value: `/@`
4. **Then (Cache eligibility):**
   - Cache status: `Eligible for cache`
   - Edge TTL: `1 hour` (3600s)
   - Browser TTL: `5 minutes` (300s)
5. Click **Deploy**.

## STEP 8: Decommission Vercel (Safe Disconnect)

Once your DNS on Cloudflare has propagated and you have verified that visiting:
- `https://innovators-global.com` (shows landing page from EC2)
- `https://innovators-global.com/@yourusername` (shows portfolio from EC2 / Cloudflare edge)
- `https://app.innovators-global.com` (shows app workspace and auth)

You can cleanly disconnect from Vercel:
1. Log into [Vercel Dashboard](https://vercel.com/dashboard).
2. Go to your project → **Settings → Domains**.
3. Remove `innovators-global.com` from Vercel.
4. *(Optional)* Pause or delete the old Vercel deployment so you are not billed.
